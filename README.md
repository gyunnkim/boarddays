# boarddays

보드게임 전적을 기록하고 관리하는 웹 서비스.

지원 게임: 듄: 임페리움 · SETI · 테라포밍 마스

## 구현된 기능

- **인증**: 이메일/비밀번호 회원가입·로그인·로그아웃, 게스트(비회원) 익명 세션 입장 (Supabase Auth).
  게스트는 매치 기록이 불가하고(회원가입 후 이용 가능) 조회 전용이며, 로그아웃 시 게스트 계정 자체가
  삭제됨(전적 데이터를 남기지 않으므로 유실 위험 없음). 회원가입/게스트 입장 폼에서 이메일(회원가입만)·
  이름·비밀번호(회원가입만)를 모두 필수로 입력받으며, 이름은 이 시점에 한 번만 정해짐(서비스
  전체에서 유일해야 하고, 이후 변경 불가)
- **대시보드**: 전적을 "100전 30승 70패 30%" 형식의 한 줄로 요약해 표시, 게임별 플레이
  횟수/승률 카드 — 카드를 클릭하면 아래 전적 기록이 해당 게임으로 필터링됨. 게임/맵/기업
  필터가 하나라도 걸려 있으면 상단 요약도 필터를 통과한 매치만으로 다시 계산되고
  "선택한 필터 기준"이라는 안내가 함께 표시됨(게임별 카드 자체는 전체 기준 유지)
  - 게임을 선택하면 그 게임의 capability(`hasMapSelection`/`hasFactions`)가 지원하는 경우에 한해
    맵/진영(기업 등) 필터 칩이 추가로 노출됨 — 게임 종류를 직접 분기하지 않고 실제로 그 게임에서
    쓰인 맵·진영만 선택지로 표시. 진영 필터는 기본적으로 참여자 누구든 그 진영을 쓴 매치를
    보여주고, "나" 칩을 함께 켜면 나 자신이 그 진영을 쓴 매치로 좁혀짐
- **전적 기록**: 매치별 사용 확장팩 badge, 참여 플레이어 전원의 순위/이름/점수/승패를 카드로 표시
  (내 결과에 따라 카드 강조 색이 달라짐). 최신 20건만 먼저 표시하고 "더보기" 버튼을 누르면
  20건씩 추가로 표시
  - 진영(듄 리더 · SETI 기관 · 테라포밍 마스 기업) 선택 여부는 게임 종류를 직접 분기하지 않고
    capability(`hasFactions`)로 판단해, 플레이어가 진영을 선택한 매치라면 게임에 관계없이
    이름 옆에 함께 표시
  - 테라포밍 마스: 사용한 맵을 확장팩 badge와 다른 색(보라색 계열)의 badge로 구분해 표시.
    2026-08-01 이전에 플레이한(played_at 기준)
    매치는 확장팩 기록이 정확하지 않아 확장팩 badge를 표시하지 않고, 그 이후 플레이한
    매치부터 표시
- **매치 입력**: 게임/확장팩 선택 → 플레이어 입력(이름, 색상, 진영, 점수) → 저장까지 하나의
  공용 폼(`match-form.tsx`)에서 게임별 UI를 하드코딩 없이 capability(`lib/domain/capabilities.ts`)
  기반으로 처리
  - 플레이어 색상: 이름 앞 정사각형 스와치 버튼을 클릭하면 사용 가능한 색상(듄 4색 · SETI 4색 ·
    테라포밍 마스 5색)이 팝오버 그리드로 펼쳐져 선택하는 방식, "순서 정하기" 버튼으로 플레이어
    순서 무작위 재배치
  - 테라포밍 마스 전용: 기업 카탈로그(기본 12종 + 확장팩별 추가 + "프로모 기업 추가" 토글로
    켜고 끄는 10종), "맵 추가" 탭에서 맵 선택(직접/랜덤 — 기본 타르시스 + 헬라스&엘리시움/
    아마조니스&보레알리스/유토피아&킴메리아 토글로 추가되는 맵. 이 3개는 확장팩이 아니므로
    "사용 확장팩" 목록/배지에는 표시되지 않음), 개척기지 뽑기, 점수 항목별 입력 + 실시간 총점
    계산, 메가크레딧(MC) 입력, 동점 시 MC 타이브레이커
  - SETI 전용: 우주기관 확장 선택 시에만 비대칭 기관 11종(오비탈 다이나믹스, 펜윅 리서치
    센터 등, `docs/games/seti.md` 참고) 선택 UI 노출
- **게임 카탈로그**: 3개 게임 + 확장팩 목록을 DB에 시드 (표시명 KR/EN 이중 언어)
- **다국어(i18n)**: KR/EN 전환 토글, 화면 전체 문구 로케일 분리
- **설정**: 내 표시 이름(display name) 조회(읽기 전용) — 이름은 가입/게스트 입장 시점에 한 번만
  정해지며, 설정 화면에서는 더 이상 수정할 수 없음. 서비스 전체 이름 유일성(unique) 제약
- **이름 기반 전적 조회**: 다른 계정이 기록한 매치라도 참가자 이름이 내 표시 이름과 같으면
  대시보드/전적 기록에서 조회할 수 있음(읽기 전용 — 수정/삭제는 여전히 매치를 기록한 계정만
  가능). "나"로 강조 표시되는 카드/배지도 매치를 기록한 사람이 아니라 현재 로그인한 사용자의
  표시 이름 기준으로 판단
- **데이터 격리**: 사용자 소유 테이블(matches, match_players, match_expansions 등) 전체에 RLS 적용
  (조회는 소유자 또는 이름이 일치하는 참가자까지 허용, 쓰기는 소유자만 가능)
- **라우트 보호**: 미인증 상태로 `/dashboard` 접근 시 `/login`으로 리다이렉트 (proxy + 레이아웃
  이중 확인)

아직 구현되지 않은 기능(다음 단계):

- 전적 상세(개별 매치) 화면 — 현재는 대시보드에 인라인 카드로만 표시되고 별도 상세 페이지는 없음
- 전적 기록 수정/삭제

## 기술 스택

Next.js (App Router) · TypeScript · Tailwind CSS · Supabase (Postgres, Auth) · Vercel

## 개발 시작하기

```bash
npm install
cp .env.example .env.local   # Supabase 프로젝트 URL/키 입력
npm run dev
```

- `.env.local`을 채우기 전에는 인증/DB 관련 페이지가 정상 동작하지 않는다.
- 스키마/RLS는 `supabase/migrations/`에 순서대로 정의되어 있다. Supabase
  프로젝트에 연결한 뒤 `supabase db push` 또는 SQL 편집기로 적용한다.
- 검증: `npm run typecheck`, `npm run lint`, `npm run build`
